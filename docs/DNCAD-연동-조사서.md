작성 2026-10-08 · 고침 2026-10-08(복원 시험 결과 반영) · 대상 스키마 0070(apiBuild `4719c449…`, 백업 내보낸 날 2026-09-28)

**한 줄 결론:** DNCAD는 블랙박스와 장치 접속점을 *별도 부품*으로 저장하고, 무손실로 담는 파일은 `.dncadbak`뿐이다. imgvec은 중립 ‘배치 명세’를 만들고, 1차 출력은 `.dncadbak`(시험 단계), 같은 명세를 사용자의 생성기(API)가 읽는 길을 병행 준비한다. 손으로 만든 백업을 DNCAD가 받아들이는지는 **2026-10-08에 확인했다** — 장치 1개 백업(`01_FA01형_한장치.dncadbak`)이 새 프로젝트로 복원되고 블랙박스·접속점이 기대한 모습 그대로 들어갔다. 방식 B를 1차 출력으로 확정한다.

## 2. DNCAD의 정체

- 웹 기반 전기 CAD. 편집기 명령은 로그인 세션 인증으로 호출하는 API이며, 사용자의 생성기는 Playwright로 편집기를 조종해 이 API를 부른다. **API 키·SDK는 없다.**
- 사용자 목적(작업 문서): 고객 도면(WSCAD·EPLAN)을 DNCAD로 옮기는 도구를 만들고 있고, **‘맞는 심볼이 없으면 블랙박스로 놓는다’(2026-09-23 결정)**. 새 판 한 도면(심볼 198개)에서 일치 148 · 근사 7 · 블랙박스 43. 즉 이 프로젝트는 그 블랙박스를 *그림에서 자동으로* 만드는 도구다.
- 블랙박스의 접속점 이름은 원본 핀표 대신 **단자 번호**를 쓴다 — ‘장치 안에서 유일해야 하므로’ (PLC 사례).

## 3. 블랙박스·장치 접속점의 데이터 (실측)

### 3.1 장치 하나를 이루는 행

한 장치 = 아래 행의 묶음이다. 장치 접속점은 블랙박스와 **같은 장치 태그를 가진 별도 부품**이다.

| 표 | 행 | 핵심 열 |
| --- | --- | --- |
| `devices` | 1 | `tag` (예 `-FA01`) |
| `components` | 1 + n | 블랙박스 1개(정의 `black_box`), 접속점마다 1개(정의 `device_connection_point`) |
| `connection_points` | n | `designation`(이름), `cp_type` = `electrical`, `potential_id` null |
| `placements` | 1 + n | 블랙박스: `x, y`(왼쪽 위), **`size {w, h}`**, 회전 0, `main_function` true. 접속점: `x, y, rotation`, `size` null |
| `graphic_anchors` | n | 접속점 배치마다 (0, 0) |

`components.definition_id`는 `masters.json`의 `globalDefinitions[{oldDefinitionId, key}]`를 통해 `black_box`·`device_connection_point` 키로 풀린다.

### 3.2 배치 규칙 (백업 14개 블랙박스에서 잰 값)

| 항목 | 관측 | 규칙으로 쓴 값 |
| --- | --- | --- |
| 단위 | 쪽 폭 297 mm = 1900 | 6.4 단위/mm |
| 높이 | 48 · 64 · 112 · 128 · 144 | 기본 112 |
| 폭 | 128 ~ 928, 모두 16의 배수 | 마지막 접속점 + 32를 16의 배수로 |
| 접속점 위치 | 모두 16의 배수, 같은 변의 간격은 **최소 32**(5 mm) | 32 단위 슬롯 |
| 위 변 | 상대 y = 0, 회전 0 | 〃 |
| 아래 변 | 상대 y = 박스 높이, 회전 **180** | 〃 |
| 오른쪽 여백 | 마지막 접속점 뒤 최소 16 | 기본 32 |
| 배치 위치 | 블랙박스 x, y 모두 16의 배수 | 〃 |
| 회전 | 접속점은 0 · 180뿐(90·270 없음). 180 중 7개는 `mirrored: true` | 0 · 180만 사용 |

| 사례 | 관측 | 대응 |
| --- | --- | --- |

## 4. 파일 형식 세 가지

| 형식 | 담는 것 | 블랙박스 크기 | 장치 접속점 | 판단 |
| --- | --- | --- | --- | --- |
| `.dncad.json` (`dncad.project.v1`) | 장치 `{tag, definitionKey, x, y}`와 배선 `{from, to}` | **없음** | 대표 부품만 내보냄 | 부적합 |
| `.dncadbak` (`dncad.backup`) | 25개 표 전부 + 전역 정의 대응 | `size {w, h}` 있음 | 부품·접속점·앵커 전부 | **적합** |
| DXF 내보내기 | 도형 (`DNC_*` 레이어, mm) | 도형일 뿐 | 접속점 개념 없음 | 외형 참고용 |

`.dncad.json`은 내보낼 때 ‘주석 건수는 형식(v1) 미지원으로 제외’, ‘이름 없는 장치 제외’, ‘끝점이 대표 부품의 단자일 때만 연결 내보냄’ 같은 경고를 낸다(Test0824-001 기준 경고 3258건). 블랙박스의 크기와 장치 접속점을 보존하지 못한다.

### `.dncadbak` 구조

```
ZIP
├─ manifest.json   format "dncad.backup" · formatVersion 1 · schemaVersion "0070" · apiBuild
│                  counts{표: 행 수} · masters{globalDefinitionKeys…} · integrity{project.json, masters.json = sha256}
├─ project.json    {"rows": {표 이름: [행…]}}   표 25개 (쓰지 않는 표는 빈 목록), 공백 없는 UTF-8 JSON
└─ masters.json    {symbols, globalDefinitions[{oldDefinitionId, key}], parts, forms}
```

- `integrity`는 두 파일 **바이트 그대로**의 sha256이다 (실제 백업으로 일치를 확인).
- 행 id는 시간순 UUIDv7, `created_at`은 `…+00:00` 마이크로초 표기다.
- 실제 백업 전체를 `imgvec device check-bak`으로 검사하면 ZIP·해시·행 수·참조 오류는 0이고, 위 3.3의 사례만 경고·참고로 나온다 — 읽기 쪽 이해가 실측과 일치한다는 뜻이다.

## 5. 출력 방식 A·B·C 평가와 결정

| 방식 | 이 PC에서 확인한 것 | 판단 |
| --- | --- | --- |
| **A. API 직접 생성** | 명령 API는 로그인 세션 기반(Clerk)이고 키·SDK는 없다. **2026-10-08 연결·전송 확인** — `imgvec device plan`이 배치 명세를 `api-build.mjs`의 명세(op)로 옮기고, 명령 54개가 모두 성공했다 | **쓸 수 있다** — 작업 중인 프로젝트에 바로 그린다 |
| **B. 가져오기 파일** | `.dncad.json`은 불가(3·4장). `.dncadbak`은 구조가 완전히 파악됨. 파일 생성·자체 검사·왕복 읽기 통과. **복원 확인 2026-10-08**: 장치 1개 백업이 새 프로젝트로 모습 그대로 복원됨 | **1차 출력으로 확정** |

**결정:** 엔진과 장치 모델은 DNCAD 방식과 무관하게 두고, 출력은 **중립 배치 명세(`dncad-device-layout/1.0`)** 한 가지로 고정한다. 이를 (B) `.dncadbak` 어댑터(`imgvec device kit`·`merge`)와 (A) 생성기 입력 어댑터(`imgvec device plan`)가 각각 읽는다. **둘 다 2026-10-08에 실제로 통했다** — B는 새 프로젝트 복원과 합치기 복원, A는 편집기 API 전송.
