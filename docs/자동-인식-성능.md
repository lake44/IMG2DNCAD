### 자리는 흐려도 번호는 선명하다 (`--from-labels`, 2026-10-09 사용자 제안)

제품 실물 사진은 단자 자리를 찾기 어렵다 — 자리로 찾으면 Pilz PNOZ X3가 11/24였다. 그런데 **번호는
선명하게 읽힌다.** 그래서 순서를 뒤집었다: 이름 줄을 먼저 찾고 거기서 접속점을 만든다 → **24/24**.

세 가지를 풀어야 했다.

| 걸림돌 | 어떻게 |
| --- | --- |
| 설명 글자가 섞인다 (`pilz`·`POWER`·`CH.1`·`USB connector`) | 변마다 **변에 가까운 두 줄**만 보고, 그 줄에서도 **덩어리마다** 이름 꼴(`_name_ok`)인 조각만 건진다 |
| 이름이 덩어리로 붙어 읽힌다 (`A1B113`) | 그 줄에서 따로 떨어진 짧은 이름에게 '이름 한 개가 몇 글자'인지 배워 그 덩어리만 쪼갠다. 한 글자 이름에게는 배우지 않는다(설명 글자까지 낱자로 쪼개진다). 줄이 통째로 붙어 있으면 그 줄에 보이는 **구멍 수**로 나눈다 |
| 단자대가 2열이다 | 변에 가까운 줄부터 이어 붙여 **한 줄로 편다**(`_unstack`). 그냥 두면 슬롯이 겹쳐 24개가 18개로 줄고 축척까지 깨진다 |

**도면 심볼에는 쓰지 않는다** — 전압 표시(`230V`)를 단자 이름으로 오인한다(실측: T1 8/8 → 5/8).

`-SR1`은 그림에 **액자**(PDF 캡처 테두리)가 있어 `--try-bodies`가 필요하다 — 그냥 두면 액자를 본체로 삼아 9/12다.

이름이 붙은 자리가 서로 반대다 — `-T1`은 접속점 **바깥**(`1·2·3·PE`), `-SC1`은 **안쪽**(`A1·T11…`).
그래서 양쪽 띠를 모두 읽고 접속점과 더 많이 짝지어지는 쪽을 고른다 (`src/imgvec/ocr.py`).

원본의 들쭉날쭉한 간격이 DNCAD 단위로도 비율 그대로 옮겨졌다:

| | 원본 px 간격 | 배치 명세 단위 간격 |
| --- | --- | --- |
| 위 변 | 343 · 85 · 171 | 128 · 32 · 64 |
| 아래 변 | 257 · 86 · 85 | 96 · 32 · 32 |

모두 격자 85.6 px = 32 단위의 정수배이고, DNCAD 규칙(16의 배수·최소 간격 32)에 맞는다.
**이름은 1~8 번호로 붙는다** — 원본의 `1·2·3·PE·31~34`를 읽으려면 OCR이 필요하다(아직 없음).

그림: `out/확인/T1.자동인식.png` (초록 = 찾은 본체, 빨강 = 찾은 접속점).

### 설명 글자는 내가 배제한다 (2026-10-09)

사람이 그림에서 설명 글자를 지워 줄 필요가 없다. 한 줄에 단자 이름과 설명이 섞여 있어도 이름만 건진다.

| 어떻게 | 왜 그렇게 |
| --- | --- |
| 변마다 **변에 가까운 두 줄**만 본다 (`LABEL_ROWS_PER_SIDE`) | 그림 안쪽의 접점표(`13 23 33 41`)·제품명(`pilz PNOZX3`)을 단자로 삼지 않는다 |
| **덩어리마다** 이름 꼴인 조각만 건진다 | `'L1 L2 L3 … USB connector'`가 한 줄이다. 줄 단위로 버리면 L1·L2·L3까지 잃는다 |
| 남은 자리가 **한 격자 위**에 있는지 본다 (`LABEL_MIN_FIT` 0.5) | 설명 글자가 우연히 이름 꼴이어도 격자에 안 맞는다 |
| 한 글자 단자(`U`·`W`·`P`·`B`)를 받는다 (`SOLO_OK`) | 전원·모터 단자는 한 글자다. 받는 글자는 `B E G K L M N P R S T U V W`로 한정했다 — `A`·`X`까지 받으면 설명 글자의 낱자가 들어온다 |
| 이름 한 개의 글자 수는 **두세 글자 이름**에게만 배운다 | 한 글자 이름에게 배우면(`U`) 설명 글자까지 낱자로 쪼개 이름으로 삼는다 (실측: SV1 아래 변) |

**파나소닉 서보 드라이버 `-SV1`** (733 × 308, 설명 글자가 단자 이름과 같은 줄에 있는 그림)

| --- | --- | --- |
| 접속점 | 4개 (단서 `stub` 4) | **17개** |
| 이름 | 없음 (자동 번호) | **17 / 17** |
| 커넥터 핀 | — | **6개** (`X1`~`X6`) |

### 접속점 종류 — 커넥터 핀을 가린다

블랙박스 접속점이 모두 일반 터미널은 아니다. 종류는 `kind`로 들고 다니고, DNCAD 심볼이 달라진다
(표는 `docs/장치-모델-스키마.md`).

그림에서 자동으로 가르는 단서는 **'…connector'라고 적힌 설명 글자**다. 그 글자의 x 범위·같은 변에 든
접속점은 커넥터 핀으로 본다 (실측: SV1의 `USB connector`·`RS232/485 connector`·`Safety function
connector`·`Interface connector`·`Encoder connection` → `X1`~`X6` 6개 모두 맞고 헛것 0).

- `--from-labels` 길은 그림 글자를 이미 읽으므로 **공짜로** 함께 가른다.
- 자리로 찾는 길에서는 `--connectors`를 켤 때만 — 그림 전체를 한 번 더 읽어야 해서
  **장당 3.4~5.5초**가 더 든다 (실측 2026-10-09, T1 한 과정 안에서 5.70초 → 9.91초).
- 모르는 종류 이름은 조용히 일반 단자로 바꾸지 않고 막는다 (검증 `E-KIND`).
- **DNCAD 복원으로 확인했다 (2026-10-09)**: SV1 백업을 복원하니 서버 scene에서 배치 18개가 모두
  `device_tag = -SV01` 하나였고 심볼은 `black_box` 1 · `connector_pin_female` 6 ·
  `device_connection_point` 11, 접속점 이름 17개가 모두 변 위에 붙었다. 복원 미리보기 `blockers` 0 ·
  `missingGlobals` 0. 프로젝트 「imgvec 커넥터핀 시험 2026-10-09 (복원 2026-10-09)」

### 배선이 안 붙은 단자도 접속점이다 (2026-10-09 레이크님 지시)

단자는 스페어이거나 아직 결선 전이라 **본체 밖으로 선이 안 나가기도 한다.** 그래도 장치 안에는 접속점으로
반드시 있어야 한다. 그래서 그런 자리는 후보로 두지 않고 **정식 접속점으로 할당한다**(`_fill_gaps`).

**Pilz PNOZ X2.8P `-U12`** (1211 × 246, 선 그림)

| | 고치기 전 | 고친 뒤 |
| --- | --- | --- |
| 접속점 | 14 / 16 | **16 / 16** |
| 이름 | 14 / 14 | **16 / 16** |
| 빠진 것 | 맨 오른쪽 접점 `41`·`42` | 없음 |

그 기둥만 본체 밖으로 선이 없다 — 화소로 쟀다: 아홉 기둥은 변 바깥(위 y2~11)에 선이 있고 `x=1129`만
비어 있다. 단자 원은 그 자리에 있었는데도 두 문에서 걸렸다.

| 걸린 문 | 왜 |
| --- | --- |
| **변 소속 배정**(`owner_side`) | 본체 오른쪽 끝이라 거리를 치수로 나누면 **오른쪽 변**이 이긴다 (위 변 25/211 = 0.12 vs 오른쪽 54/1084 = 0.05) |
| **'변선 제외' 문턱**(`min_v`) | 변 위에 딱 걸린 줄기는 본체 변 선으로 보고 버린다 |

그래서 **줄과 격자를 먼저 정한 뒤**, 그 격자의 **빈자리에 한해** 두 문을 거치지 않은 후보까지 본다.
대신 셋으로 좁혔다 — ① 글자 획(`glyph`)이 아닐 것 ② **본체 변 안**일 것 ③ 그 줄과 **같은 깊이 띠**일 것.
셋을 빼면 본체 안 설명 글자(`PILZ SAFETY RELAY`)와 바깥 장치 이름(`U12`)이 격자에 우연히 맞아 들어온다
(실측: 둘 다 들어왔다 — 헛검출 3개).

**퇴보 없음** (같은 날 실측): T1 8/8 · SC1 16/16 · SR1 12/12 · AB1 16/16 (모두 헛검출 0 · 변 틀림 0) ·
PZ1 24/24 · SV1 17 · 샘플 18종 190/220(86%) · 헛검출 12 — 고치기 전과 같은 값이다.

## 어떤 단서로 찾나

| 단서 | 무엇 | 서열 |
| --- | --- | --- |
| `circle` | 작은 원 — 선 그림의 단자 | 1.6 |
| `dot` | 본체 변 위의 **굵어진 곳** — 채워진 점(●)으로 그린 단자. 점이 둘 이상이면 **다른 단서는 버린다** | 1.55 |
| `stub` | 본체 변에 한쪽 끝이 붙은 짧은 수직·수평 선의 **바깥 끝** — 블록도의 줄기 | 1.5 |
| `blob` | 둥근 색 덩이 — 일러스트의 나사 머리 | 1.0 |
| `glyph` | 찌그러진 색 덩이 — 글자 획 | 0.3 |

줄을 정한 **뒤에는** 그 격자의 빈자리를 `circle`·`dot`·`blob`·`stub` 어느 것으로든 메운다 — 배선이 안
붙은 단자를 놓치지 않기 위해서다 (위 '배선이 안 붙은 단자' 참고). 글자 획은 그때도 받지 않는다.

한 줄 안에 윗 단서가 둘 이상 있으면 아랫 단서는 버린다.

| 고친 것 | 왜 그랬나 | 효과 |
| --- | --- | --- |
| **단서 서열** | 글자 획이 접속점으로 둔갑했다 | 헛검출 201 → 49 |
| **조각난 변 모으기** (본체) | 선 그림의 본체 변은 줄기에 잘려 토막난다 | 본체 9/18 → 18/18, 최악 516 px → 4.3 px |

| **후보는 제 변 하나에만** (`owner_side`) | 한 점이 네 변 모두의 후보가 되어, 멀리 떨어진 두 점이 '넓게 퍼진 줄'로 이겼다. 거리는 **그 변에 수직인 본체 치수로 나눠** 견준다 — 그러지 않으면 길쭉한 장치에서 뒤집힌다 | 변 틀림 11 → 0 |

| **격자 후보에 간격의 약수도** | 빈 자리가 많으면 격자가 어떤 간격에도 그대로 나타나지 않는다 (`-SC1` 아래 변: 155·94·125·93·156·63이 모두 31.5의 배수) | `-SC1` 9/16 → **16/16**, 샘플·T1 손해 없음 |
| **이름 읽기** (`ocr.py`) | 이름이 없으면 사람이 16개를 다 쳐 넣어야 한다 | `-T1` 8/8, `-SC1` 16/16 |
| **본체 후보 여럿** (`--try-bodies`) | PDF 매뉴얼 캡처는 바깥에 **액자**가 있다. 가장 큰 사각형을 본체로 삼으면 변이 접속점에서 멀어진다 | `-SR1` 9/12 → **12/12** |
| **원은 '변선 제외' 문턱 면제** (`_floor`) | 단자 원이 본체 변에 딱 붙어 그려지면(2.5 px) 진짜 단자가 통째로 걸러지고 안쪽 잡음이 대신 잡혔다 | `-SR1` 9/12 → 12/12, 다른 그림은 손해 없음 |
| **본체 후보를 덮임 우선으로 정렬** | 넓이만 보면 액자와 본체의 변을 **섞은** 사각형들이 앞을 막아 진짜 본체가 후보에서 빠진다 | `-SR1` 헛검출 2 → **0**, 본체 오차 44 → 4.9 px |
| **점(●) 단자** (`dot_candidates`) | 점이 변선 위에 그려지면 이진화에서 선과 한 덩어리가 되어 연결 성분으로는 안 잡힌다. 선은 가늘고 점은 굵으므로 **두께**로 가른다. 봉우리 **폭**도 봐야 한다 — 줄기가 변에 닿는 자리(폭 3)도 두껍지만 진짜 점은 폭 5~6이다 | `-AB1` 4/16 → **16/16**, 폭 문턱을 놓쳤을 때 T1 이름 8 → 7 |
| **이름으로 자리 정하기** (`pins_from_labels`) | 제품 실물 사진은 자리가 흐려도 번호는 선명하다 | Pilz 사진 11/24 → **24/24** |
| **붙어 읽힌 이름 쪼개기** (`ocr.py`) | 이름이 촘촘하면 `A1 A2`가 `A1A2` 한 덩어리로 읽힌다. 글자 수가 덮은 접속점 수로 나누어떨어지면 고르게 쪼갠다 | `-SR1` 이름 7/12 → **12/12** |
| **깊이·변 배정을 '그 변에 수직인 치수'로** (`perp_size`) | 짧은 변 하나로 재면 길쭉한 장치에서 한쪽이 턱없이 얕아져 안쪽 단자를 놓친다 | 샘플 185 → **190**, 헛검출 14 → **12** |

0.25까지 낮추면 192/220(87%)이 되지만 헛검출이 16으로 는다. **빠진 자리를 찍는 것이 틀린 자리를 찾아 지우는 것보다 쉬워서** 0.35를 골랐다.

격자 방식은 샘플 점수를 1점 깎고 헛검출을 5 늘리지만(`ill_io_module` 2→0, `deg_ill_safety_blur` 헛 8→10),
**실제 도면 심볼이 2/8에서 8/8이 되므로** 그쪽을 택했다 — 이 도구가 실제로 받는 입력은 도면 심볼이다.

## 아직 못 하는 것

| 무엇 | 왜 | 지금은 |
| --- | --- | --- |
| 제품 사진에서 **자리로** 찾기 | 단자대가 2열이고 본체 깊숙이 있어 어느 변 소속인지 가르기 어렵다 | `--from-labels`로 **이름에서** 만든다 (Pilz 사진 24/24) |
| 나사가 잘게 갈라지는 2열 사진 | 조각이 병합 반경 밖으로 흩어진다 | 작업대에서 사람이 찍는다 |
| 글자 수가 안 맞게 붙어 읽힌 이름 | `A1 A23`처럼 길이가 접속점 수로 나누어떨어지지 않으면 쪼갤 수 없다 | 작업대 목록에서 고친다 |
| 글자 인식기가 틀리게 읽은 이름 | `GND`를 `CND`로 읽으면 이름 꼴이 아니라 버려진다 (실측: SV1) | 작업대에서 한 칸 더한다 |
| 커넥터 핀을 **그림만 보고** 가리기 | 단서는 '…connector'라고 적힌 글자뿐이다. 글자가 없으면 모양만으로는 못 가린다 | 핀표 `kind` 열에 적는다 |
| 축척 | 그림만으로는 알 수 없다 | `--mm-per-px`·`--body-width-mm`·`--pin-pitch-mm` 중 하나 |
| 기울어진 스캔·원근 | 보정이 없다 | 〃 |

## 다시 재려면

```powershell
imgvec device autotest samples\set              # 위 표
imgvec device autotest samples\set --xy         # 2차원 거리로
imgvec device autotest samples\set --tol 10     # 허용 오차를 좁혀서
imgvec device autotest <폴더> --try-bodies      # 액자가 있는 그림(PDF 캡처)
imgvec device auto 사진.png --from-labels       # 제품 실물 사진 — 이름에서 자리를 정한다
```

`tests/test_detect.py`의 `test_autotest_numbers_do_not_regress`가 네 종(블록·선·일러스트·아이콘)을
빠짐없이 찾는지 지킨다 — 뒷걸음질 치면 시험이 깨진다.
