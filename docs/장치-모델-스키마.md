# 장치 모델 스키마

그림 하나가 DNCAD의 ‘블랙박스 + 장치 접속점’이 되기까지 네 가지 파일을 거친다. 이 문서는 각 파일의 모양과 약속(좌표계·단위·검증 코드)을 정한다. 기계가 읽는 정의는 `docs/schema/*.json`(JSON Schema 2020-12)이고, `tests/test_schemas.py`가 실제 출력이 이 스키마와 맞는지 매번 확인한다.

작성 2026-10-08 · 모델 버전 `device-model/1.0` · 0단계 초안(계획서 5장)에서 2단계 구현으로 확정

```
그림 ──(접속점·본체·축척 지정)──▶ 장치 명세 ──(벡터화+축척)──▶ 장치 모델 ──(DNCAD 규칙)──▶ 배치 명세 ──▶ DNCAD
        pins.csv / pick            device-spec/1.0          device-model/1.0        dncad-device-layout/1.0
                                                            + 주석 SVG                (.dncadbak 시험 백업 등)
```

## 1. 좌표계와 단위

| 항목 | 약속 | 이유 |
| --- | --- | --- |
| 길이 단위 | mm (장치 모델) · DNCAD 단위(배치 명세) | DNCAD 단위는 6.4/mm: 접속점 간격 5 mm = 32, 격자 2.5 mm = 16, 쪽 폭 297 mm = 1900 (실측) |
| 원점 | 본체(블랙박스) 왼쪽 위 모서리 | DNCAD 배치가 왼쪽 위 기준이다 (실측) |
| y 방향 | **아래가 +** | DNCAD·SVG·이미지가 모두 y 아래이므로 변환 오류가 없다. 계획서 초안의 ‘y 위’는 이 이유로 바꿨다 |
| 각도 | 라디안, 점 = (cx + r·cos a, cy + r·sin a) | y가 아래이므로 각도가 커지면 화면에서 시계 방향 |
| 변 이름 | `top`·`bottom`·`left`·`right` | 입력은 상·하·좌·우도 받는다 |
| 접속점 위치 | 본체 **경계 위** 부착점 (x, y) | DNCAD 접속점은 블랙박스 위·아래 변에 놓인다. 그림에서 보인 위치는 `src`에 따로 둔다 |

## 2. 장치 명세 `device-spec/1.0` (입력)

사람이 쓰거나 `imgvec device pick`이 만든다. `imgvec device build --spec`이 읽는다. 스키마: `docs/schema/device-spec.schema.json`.

| 필드 | 뜻 |
| --- | --- |
| `name` | 장치 이름 |
| `image` | 그림 파일(명세 파일 기준 상대 경로) |
| `scale` | 축척 지정 방법 **하나** (아래 표) |
| `body_px` | 본체 사각형 `[x0, y0, x1, y1]` (그림 픽셀). 없으면 도형에서 추정, 못 찾으면 오류 |
| `preset` | 벡터화 프리셋 `auto`·`lineart`·`illustration`·`photo` |
| `graphics` | `false`면 외형 도형 없이 본체와 접속점만 |
| `pins[]` | 접속점. 위치는 `offset_mm` > (`x_mm`, `y_mm`) > (`x_px`, `y_px`) 순으로 우선. `side`가 없으면 가장 가까운 변 |

| 축척 지정 | 필요한 것 | 비고 |
| --- | --- | --- |
| `mm_per_px` | 값 하나 | 해상도를 아는 경우 |
| `ref` = `[x1, y1, x2, y2, mm]` | 그림 위 두 점과 실제 거리 | 가장 일반적. 화면 도구가 만든다 |
| `body_width_mm` | `body_px` | 제조사 자료의 본체 폭을 쓸 때 |
| `pin_pitch_mm` | 같은 줄 접속점의 `x_px`와 `group` | 단자 간격(예: 5.08 mm)을 쓸 때 |

접속점 CSV 열: `name`(필수), `side`, `offset_mm`, `x_mm`, `y_mm`, `x_px`, `y_px`, `kind`, `label`, `group`. 머리글은 `이름`·`변`·`그룹` 같은 한글 별칭도 받고, 구분자는 쉼표·세미콜론·탭, 인코딩은 UTF-8 또는 CP949를 자동 판별한다. `#`로 시작하는 줄은 주석이다.

## 3. 장치 모델 `device-model/1.0`

스키마: `docs/schema/device-model.schema.json`. 엔진이 만드는 중간 데이터이며 DNCAD 방식이 바뀌어도 이 파일은 바뀌지 않는다.

```json
{
  "schema": "device-model/1.0",
  "name": "block_inverter",
  "unit": "mm",
  "coords": "origin=body top-left, x right, y down",
  "body": { "shape": "rect", "w": 60.0, "h": 38.0 },
  "pins": [
    { "name": "R", "side": "top", "x": 12.0, "y": 0.0, "src": [12.0, -9.0] }
  ],
  "graphics": [
    { "type": "path", "closed": false,
      "segs": [ { "type": "line", "p0": [12.02, -9.09], "p1": [12.02, 0.03] } ] },
    { "type": "circle", "c": [30.0, 19.0], "r": 6.0 }
  ],
  "texts": [],
  "meta": { "imgvec": "0.1.0", "source_image": "block_inverter.png",
            "calibration": { "mm_per_px": 0.1, "method": "manual" } }
}
```

| 요소 | 필드 | 설명 |
| --- | --- | --- |
| `body` | `shape`, `w`, `h` | 직사각형(`rect`)만 DNCAD 블랙박스로 확인됨. 다른 모양은 경고 |
| `pins[]` | `name` | 접속점 이름 = DNCAD `designation`. 장치 안에서 유일 |
| | `side`, `x`, `y` | 붙은 변과 경계 위 부착점(mm) |
| | `kind` | DNCAD `cp_type`. 기본 `electrical`(기본값이면 쓰지 않음) |
| | `group` | 단자열(예: `P3`). 한 변에 줄이 여럿일 때 배치 순서를 정한다 |
| | `label`, `src` | 설명, 그림에서 보인 위치(mm) |
| `graphics[]` | `circle` · `path` | 경로는 `line`(`p0`,`p1`)과 `arc`(`c`,`r`,`a0`,`a1`) 조각의 목록 |
| `texts[]` | `value`, `x`, `y`, `height`, `rotation` | 글자(현재는 읽기·쓰기만 지원) |
| `meta` | | 도구 버전, 원본 그림, 축척 근거, 벡터화 품질 등 출처 기록 |

**외형 도형과 DNCAD:** DNCAD 블랙박스는 크기를 가진 직사각형이고 그 안에 사용자 도형을 담지 않는다(실측). 그래서 `graphics`는 주석 SVG와 화면 확인용이며, DNCAD에 외형까지 옮기려면 심볼 가져오기(DXF·PDF) 경로가 따로 필요하다 — 3단계에서 조사한다.

### 주석 SVG

모델을 SVG로도 저장한다. Inkscape 등에서 접속점을 끌어 옮기거나 이름을 고친 뒤 `imgvec device from-svg`로 되읽는다. SVG 좌표 = 모델 좌표(mm)이고 viewBox 원점만 여백만큼 음수다.

| `data-role` | 요소 | 읽을 때 |
| --- | --- | --- |
| `body` | 본체 `<rect>` | **이 사각형의 왼쪽 위가 원점.** 전체를 옮기거나 확대해도 안전하다 |
| `graphics` | 도형 그룹 | path(M·L·H·V·A·C·S·Q·T·Z)·circle·ellipse·rect·line·polyline·polygon을 도형으로 읽는다 (`transform`은 모두 합성) |
| `pin` | `<g>` 안의 `<circle>` | `data-name`, `data-side`, `data-kind`, `data-group`, `data-label`. 옮겨 놓았으면 가장 가까운 본체 변으로 다시 붙인다 |
| `pin-src` | 점선 | 그림에서 보인 위치와 부착점을 잇는 안내선 (읽을 때 무시) |
| `text` | `<text>` | 글자 |

## 4. 배치 명세 `dncad-device-layout/1.0`

장치 모델을 DNCAD 규칙으로 풀어 쓴 중립 파일이다. 스키마: `docs/schema/dncad-device-layout.schema.json`.

| 규칙 | 값 | 근거 |
| --- | --- | --- |
| 블랙박스 크기 | 폭 = (마지막 슬롯 × 32 + 5 mm × 6.4)를 16의 배수로 올림, 높이 기본 112 | 실측 높이 112·144, 폭 ≥ 마지막 접속점 + 16 |
| 접속점 슬롯 | 변을 따라 32 단위(5 mm)마다 하나. 원래 위치에 가까운 슬롯, 겹치면 오른쪽으로 | 실측: 간격 32, 대부분 32에서 시작(예외 -KF03은 64, -MA02는 544) |
| 위 변 | `y = 0`, 회전 0 | 실측 |
| 아래 변 | `y = 박스 높이`, 회전 180 | 실측 |
| 단자열(`group`) | 같은 변의 줄은 CSV 순서대로 이어서 놓는다 | 한 변에 여러 줄이 겹쳐 보이는 단자대 대응 |
| 왼쪽·오른쪽 변 | 배치하지 않는다. `--remap-lr`이면 왼쪽→위, 오른쪽→아래로 옮긴다 | DNCAD 실측에 90·270 회전 접속점이 없다 (미확인) |

## 5. 검증 코드

`imgvec device build`·`validate`가 출력한다. **오류가 있으면 종료 코드 1**이고 DNCAD로 보내지 않는다.

| 코드 | 수준 | 뜻 |
| --- | --- | --- |
| `E-NOPIN` | 오류 | 접속점이 하나도 없다. 접속점 0개 블랙박스는 DNCAD 검증에서 막힌다 (2026-09-21 500쪽 도면 사고) |
| `E-DUP` | 오류 | 한 장치 안에 같은 접속점 이름. 생성기 API가 거부한다. `--allow-dup-names`이면 `W-DUP` 경고 (기존 백업에는 중복이 있다) |
| `E-NAME` · `E-SIDE` · `E-BODY` | 오류 | 빈 이름 · 알 수 없는 변 · 본체 크기가 0 이하 |
| `E-OUT` · `E-EDGE` | 오류 | 접속점이 변의 범위 밖 · 본체 경계에서 0.5 mm 넘게 떨어짐 |
| `E-OVERLAP` | 오류 | 같은 줄의 두 접속점이 1 mm 미만으로 붙음 |
| `E-NOLAYOUT` | 오류 | 배치할 수 있는 접속점이 없음 |
| `W-PITCH` · `W-MARGIN` | 경고 | 같은 줄 간격이 3.75 mm 미만(1 mm 이상) · 모서리에서 2 mm 미만(권장 2.5 mm) |
| `W-SIDE` | 경고 | 왼쪽·오른쪽 변은 DNCAD에서 확인되지 않아 배치에서 제외 |
| `W-SHAPE` · `W-HEIGHT` · `W-MANY` | 경고 | 직사각형이 아님 · 너무 낮음 · 접속점 64개 초과 |
| `W-NAME` · `W-NAME-SPACE` · `W-NAME-LEN` | 경고 | 장치 이름 없음 · 이름에 공백·줄바꿈 · 12자 초과 |
| `I-GRID` · `I-SLOT` · `I-MOVED` · `I-GROUPS` · `I-GFX` | 참고 | 격자에 안 맞아 슬롯으로 맞춤 · 슬롯 이동량 · 변 옮김 · 단자열 여럿 · 도형이 본체 밖 |

## 6. DNCAD 쪽 대응 (실측, 스키마 0070)

| 모델 요소 | DNCAD 행 | 값 |
| --- | --- | --- |
| 장치 | `devices` | `tag`(예 `-TA01`) |
| 본체 | `components`(정의 `black_box`) + `placements` | 배치 `x, y`(왼쪽 위), `size {w, h}`, 회전 0, `main_function` true |
| 접속점 | `components`(정의 `device_connection_point`) + `connection_points` + `placements` + `graphic_anchors` | 접속점 부품마다 `designation`, `cp_type` electrical, 배치 `x, y, 회전`, 앵커 (0, 0) |
| 외형 도형 | (없음) | 블랙박스에는 담을 곳이 없다 → 위 3장 참고 |
| 이름 | (없음) | 블랙박스 `description`은 실제 백업이 모두 비워 둔다. `kit --describe`로 쓸 수는 있다 |

자세한 근거와 아직 확인하지 못한 점은 `docs/DNCAD-연동-조사서.md`.

## 7. 버전 정책

- 파일마다 `schema`에 이름과 버전을 쓴다. 읽는 쪽은 주 버전(`1.`)만 맞으면 읽는다.
- 필드를 더하면 부 버전(`1.1`), 뜻을 바꾸거나 빼면 주 버전(`2.0`)을 올리고 스키마 파일을 같이 고친다.
- `tests/test_schemas.py`는 샘플 20종의 명세·모델·배치 명세와 벡터화까지 거친 결과가 스키마를 통과하는지, 잘못된 문서는 막히는지 확인한다.
