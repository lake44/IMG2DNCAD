# 변환 속도 (2026-10-09 실측)

잰 방법: `imgvec device run`으로 그림 한 장을 DNCAD 백업까지. 8코어 리눅스, 그림 다섯 장.

**한 줄 결론:** 같은 결과를 **75.4초 → 48.5초(36% 단축)**로 줄였다. 정확도는 하나도 깎지 않았다 —
빠르지만 이름을 틀리는 길은 셋 다 되돌렸다.

## 어디에 시간이 쓰이나

| 단계 | 시간 | 비중 | 무엇 |
| --- | --- | --- | --- |
| **이름 읽기** | 26.5초 | 53% | 변마다 바깥·안쪽 띠를 읽는다. 호출당 1.1초가 **고정**이다 (띠 크기와 거의 무관) |
| **벡터화** | 22.7초 | 46% | 리본·골격화가 대부분 (SR1 5.5초, PZ1 4.8초) |
| 라벨·자리·읽기 | 0.6초 | 1% | |

## 줄인 것

| 무엇 | 어떻게 | 효과 |
| --- | --- | --- |
| **같은 그림을 두 번 벡터화** | `device run`이 자동 인식에서 한 번, 장치 만들기에서 또 한 번 돌리고 있었다. 작업대가 결과를 들고 있다가 넘긴다 | 장당 1~12초 |
| **읽기를 동시에** | 변 2개면 띠 4개를 따로 읽어 4.3초였다. `read_bands`가 동시에 읽는다 (`workers=4`가 최선, 실측) | 22.1 → 17.6초 |
| **다시 인식할 때** | 작업대에서 자동 인식을 또 누르면 벡터를 다시 만들었다 | SR1 20.3 → 6.0초 |

## 해보고 되돌린 것 — **정확도를 깎기 때문**

| 시도 | 속도 | 왜 버렸나 |
| --- | --- | --- |
| 그림 전체를 한 번만 읽기 | 22 → 10초 | 분할이 거칠어 `1`→`L`, SC1 이름 16 → 9 |
| 띠를 한 장으로 이어 붙여 1회 | 22 → 8.4초 | 캔버스가 커지면 인식기가 다르게 자른다 (`Y1`→`rossfault`). 간격을 48·96·160으로 넓혀도 그대로 |
| 벡터화 확대 1200으로 | −25% | SR1 접속점 12 → 9, 이름 12 → 4 |
| 벡터화 확대 900·끄기 | −30~40% | SC1 이름 반토막, SR1·PZ1은 **본체도 못 찾음** |
| 색 수 10 → 4 | 없음 | 실제 색이 이미 적어 팔레트가 작다 |

**확대는 곧 정확도다.** SR1처럼 작고 흐린 그림(587 × 446)은 3배로 키워야 단자가 보인다.

## 커넥터 핀 가리기를 켜면 (2026-10-09)

`--connectors`는 그림 **전체**를 한 번 더 읽는다 — 실측 장당 3.4~5.5초(그림 6종), T1을 한 과정 안에서
번갈아 재면 5.70초 → 9.91초. 확대를 1·2·3으로 바꿔도 4.6초 그대로라 **글자 찾기 단계가 비용**이다.
그래서 기본은 꺼 두고, `--from-labels`처럼 **이미 그림 글자를 읽는 길에서만 공짜로** 함께 가른다.

> 이 날 측정은 다른 작업이 함께 돌아(부하 12, 8코어) 절대 시간이 위 표보다 부풀어 있다.
> 같은 조건에서 번갈아 잰 **차이**만 쓴다.

## 더 줄이려면

| 길 | 얻는 것 | 잃는 것 |
| --- | --- | --- |
| 낮은 확대로 먼저 → 모자라면 다시 | 잘 되는 그림(T1·AB1·PZ1)이 빨라진다 | 안 되는 그림(SR1)은 두 번 돌아 **더 느리다** |
| 이름을 안 읽기 (`--no-names`) | 장당 4~6초 | 접속점 이름이 번호만 남는다 |
| 더 빠른 글자 인식기 | 읽기 53%의 대부분 | 설치가 무거워지거나 정확도가 바뀐다 |

**이름이 필요 없는 일괄 작업이라면 `--no-names`가 가장 싸다** — 자리는 그대로 100%다.

## 다시 재려면

```powershell
imgvec device run 그림.png --pin-pitch-mm 5.08 -o out\시험     # 한 장 끝까지
imgvec device run 그림.png --no-names --pin-pitch-mm 5.08      # 이름 없이
```
